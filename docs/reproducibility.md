# 实验复现、指纹与 checkpoint 兼容性

可复现结果必须同时固定代码、数据、训练身份和评估身份；只有 checkpoint 不能证明结果来自同一实验。

## 每次正式实验应记录

1. Git 提交哈希和工作区是否有未提交修改；
2. Python、PyTorch、CUDA、GPU 型号和操作系统；
3. 数据集完整名称及关键数组 SHA-256；
4. 训练 YAML、模型、随机种子、run tag 和完整命令；
5. 最佳指标、停止原因、最佳 epoch 和 checkpoint 校验值；
6. 评估 YAML、参数、网格规模、方法、边界后处理及质量选择；
7. `results.json`、跨种子汇总表和论文图路径。

正式任务先使用 `--dry-run` 检查计划，再运行实际命令。论文表格优先报告三个随机种子的均值和标准差；单种子只用于调试或预实验。

## 指纹与复用

训练指纹覆盖数据集身份、模型结构、损失、采样、优化器和关键训练参数。评估指纹覆盖 checkpoint、方法、参数、网格、映射、后处理和质量选择。指纹一致且结果完整时可以复用；不一致时不得把旧结果当成新配置结果。

`--force` 仅用于确认需要替换的运行。论文结果应使用新 tag 或新实验目录，不能覆盖已经引用的配置和结果。

## checkpoint 兼容性

以下设置通常改变参数名称或形状，旧 checkpoint 不能直接严格加载：

- 模型类别及二维/三维维度；
- `branch_dim`、`output_dim`、隐藏层宽度和层数；
- 边界输入点数和训练网格；
- 自注意力、`weight_head_mlp_enabled` 和投影 MLP 结构；
- 坐标增强模式及输入维度；
- MeshONet 分支融合结构。

以下设置未必改变张量形状，但会改变科学身份，不能共享训练指纹：映射模式、目标插值、采样分布、损失及有限差分步长、学习率、种子、数据子集、停止规则和评估边界后处理。

迁移旧模型时应保留原 YAML 和运行清单，比较参数名与形状，先执行单样本小批量前向，再完整评估边界误差和网格合法性，并写入新 tag。不要用 `strict=False` 静默掩盖结构差异。多模型显式加载应分别使用模型专属 checkpoint 参数。

## 数据与模型制品

`data/raw/`、`outputs/` 和大型实验结果不由 Git 分发。跨机器同步时至少记录相对路径、字节数、SHA-256、许可/来源、Git 提交和配置。

```powershell
Get-FileHash data/raw/2D/<dataset>/dataset.npy -Algorithm SHA256
Get-FileHash outputs/checkpoints/2D/<checkpoint>.pt -Algorithm SHA256
```

```bash
sha256sum data/raw/2D/<dataset>/dataset.npy
sha256sum outputs/checkpoints/2D/<checkpoint>.pt
```

公开发布时应提供制品下载位置和校验清单；未分发大型制品时，至少提供可复现生成命令与预计耗时。

## 发布检查单

- 提交实际使用的 YAML、命令和随机种子；
- 提供数据或生成命令及校验值；
- 区分 raw 输出和边界后处理结果；
- 区分节点数和单元数，例如 `201×201` 节点对应 `200×200` 单元；
- 报告训练/推理时间及硬件；
- 不混用历史消融配置与当前正式配置；
- 保留原始 `results.json`，由程序生成论文表格。
